# Lessons log (append after every event; newest first)

Each event has two parts. **Rules** are general and apply to every new event. **Case notes** are facts from that event: never use them as facts elsewhere without re-verifying. Only write what is verified from the event's files or the user's account; mark anything reported second-hand.

## Innovative Allnighter 2026 (UL EF), Kolektor Etra challenge, 16-17 Oct 2026, 2nd place

### Rules
- Copy format limits (pitch minutes, Q&A, file naming, deadlines) from the organiser's rules in phase 1, with the source line. Never from a kit or an assumption.
- Every deliverable has an internal deadline at least 60 minutes before the official one, and a named owner.
- After wave 1, pick one beachhead customer or case and go deep: who decides, when, numbers, a first step. A long shallow list is a backup slide, not the answer.
- Use the company's own assets (existing customers, projects, relationships, logistics) as levers. Insiders reward ideas that build on what they already have.
- Before locking the spine idea, search whether competitors already sell that exact mechanism. If they do, it is not the innovation.
- Red-team the core insight on a different model and search whether it is already reported in the trade press.
- Grade every field A/B/C. A C (inference) is never presented as a finding, even in a column header.
- Copy numbers from the ledger by ID; run numcheck on the final files. Numbers mutate across merges.
- Tags like "[fact]" in a merged file are not evidence; the ledger row with an opened URL and a quote is.
- For anything a jury sees, run a second blind check on a different model.
- Teammates' agents claim tasks on the board and read the findings digest first, or they duplicate work.
- Verbal statements by company people: label them, ask permission to quote, never use them as headline numbers.
- Never guess the company's internals in front of its own people; put them on an "assumptions to confirm with you" slide.
